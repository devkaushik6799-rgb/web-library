TOPIC 2.1

Lists

Definition: HTML Lists group related items semantically into ordered sequences (<ol>), unordered bulleted collections (<ul>), or term-description pairs (<dl>).

Important Tags & Attributes

  • <ul> & <li>: Unordered list and list item.
  • <ol type="1|A|a|I|i" start="N" reversed>: Ordered list with customizable numbering style and starting value.
  • <dl>, <dt>, <dd>: Description list, term, and definition.
lists-example.html
<h3>Web Stack</h3>
<ul>
  <li>HTML5</li>
  <li>CSS3
    <ol type="a">
      <li>Flexbox</li>
      <li>CSS Grid</li>
    </ol>
  </li>
</ul>
<dl>
  <dt>DOM</dt>
  <dd>Document Object Model tree representing the page.</dd>
</dl>
Browser Output Description Renders "HTML5" and "CSS3" with bullet points; indented beneath "CSS3" appear "a. Flexbox" and "b. CSS Grid". Below that, "DOM" renders left-aligned with its definition indented underneath.

TOPIC 2.2

Tables

Definition: HTML Tables organize two-dimensional tabular data into rows and columns using <table>, header cells (<th>), and data cells (<td>).

Structure, Tags & Attributes

  • Semantic Sections: <caption> (title), <thead> (header rows), <tbody> (body rows), <tfoot> (summary/totals).
  • Cell Spanning: colspan="n" merges n horizontal columns; rowspan="n" merges n vertical rows.
  • Accessibility: Use scope="col" or scope="row" on <th> so screen readers associate headers with data cells.
table-example.html
<table border="1">
  <caption>B.Tech Web Tech Marks</caption>
  <thead>
    <tr><th scope="col">Roll No</th><th scope="col">Name</th><th scope="col">Score</th></tr>
  </thead>
  <tbody>
    <tr><td>101</td><td>Priya</td><td>92</td></tr>
    <tr><td colspan="2">Class Average</td><td>92</td></tr>
  </tbody>
</table>
Browser Output Description Displays a bordered grid with a centered caption above three bold column headers ("Roll No", "Name", "Score"), a data row for Priya, and a bottom row where "Class Average" spans across the first two columns.

TOPIC 2.3

Images

Definition: HTML Images embed raster or vector graphics into web pages using the void <img> element, semantic <figure> containers, or responsive <picture> elements.

Important Attributes & Elements

  • src: Path or URL to the image file (JPEG, PNG, WebP, SVG, AVIF).
  • alt: Mandatory alternative text for screen readers and fallback when the image fails to load.
  • width & height: Reserves layout space to prevent Cumulative Layout Shift (CLS).
  • loading="lazy": Defers off-screen image loading to improve page speed.
  • <map> & <area>: Creates clickable image maps with geometric coordinates (rect, circle, poly).
images-example.html
<figure>
  <img src="assets/architecture.png" alt="Three-tier web architecture diagram"
       width="600" height="340" loading="lazy">
  <figcaption>Figure 1: Client, Application Server, and Database Tiers</figcaption>
</figure>
Browser Output Description Renders the 600×340 diagram inside a semantic figure block with the caption text neatly displayed directly beneath the image.

TOPIC 2.4

Forms

Definition: HTML Forms (<form>) collect structured user input—such as login credentials, registrations, or search queries—and submit it to a server or JavaScript handler.

Key Attributes & Controls

  • action: Destination URL that processes submitted form data.
  • method: HTTP method—GET (appends data to URL query string, ideal for searches) or POST (sends data in HTTP request body, required for passwords/files).
  • Controls: <input> (text, email, password, number, radio, checkbox, date, file), <select>/<option>, <textarea>, <label for="...">, and <button type="submit">.
  • HTML5 Validation: Attributes like required, minlength, pattern, and min/max validate input natively before submission.
form-example.html
<form action="/register" method="POST">
  <label for="email">University Email:</label>
  <input id="email" name="email" type="email" required placeholder="student@uni.edu">

  <label for="sem">Semester:</label>
  <select id="sem" name="semester">
    <option value="5">5th Semester</option>
    <option value="6">6th Semester</option>
  </select>
  <button type="submit">Register</button>
</form>
Browser Output Description Displays an email input box with placeholder text, a dropdown selector for Semester, and a clickable "Register" button; submitting without a valid email triggers a native browser validation tooltip.

TOPIC 2.5

Frames

Definition: Frames allow a web page to display another independent HTML document inside a defined region of the browser window.

Legacy <frameset> vs. Modern <iframe>

  • HTML4 Framesets (Deprecated): <frameset cols="25%,75%"> and <frame> replaced <body> to split the viewport into panes. Removed in HTML5 due to broken bookmarking, accessibility, and printing issues.
  • HTML5 Inline Frames (<iframe>): Embeds external content (videos, maps, payment widgets) inside a normal page.
  • Security Attributes: sandbox restricts scripts/forms inside the frame; allow controls camera/fullscreen permissions; title provides screen-reader context.
iframe-example.html
<iframe src="https://example.edu/lab-manual.html"
        title="Web Technology Lab Manual"
        width="100%" height="360"
        sandbox="allow-scripts allow-same-origin"
        loading="lazy">
</iframe>
Browser Output Description Renders a scrollable 360px-tall embedded viewport inside the parent page displaying the external lab manual document under strict sandbox restrictions.

TOPIC 2.6

Dynamic HTML with JavaScript

Definition: Dynamic HTML with JavaScript uses client-side JavaScript event handlers and DOM APIs to update page content, styles, and structure interactively without reloading the page from the server.

Core Mechanisms

  • Selecting Elements: document.getElementById(), document.querySelector().
  • Event Handling: Attaching listeners via addEventListener("click", fn), input, or submit.
  • DOM Mutation: Changing textContent, innerHTML, classList.toggle(), or creating nodes with document.createElement().
dhtml-counter.html
<p id="status">Topics studied: 0</p>
<button id="incBtn" type="button">Complete Topic</button>

<script>
  let count = 0;
  const statusEl = document.getElementById("status");
  document.getElementById("incBtn").addEventListener("click", () => {
    count++;
    statusEl.textContent = `Topics studied: ${count}`;
    statusEl.style.color = "#55D6BE";
  });
</script>

TOPIC 2.7

CSS (Cascading Style Sheets)

Definition: CSS is a stylesheet language that controls the visual presentation, typography, colors, and responsive layout of HTML and XML documents, separating presentation from content.

Three Types of CSS

  1. Inline CSS: Applied via the style="..." attribute on a single element (highest specificity, hard to maintain).
  2. Internal (Embedded) CSS: Placed inside a <style> block in the document <head>.
  3. External CSS: Stored in a separate .css file linked with <link rel="stylesheet" href="style.css"> (best practice for caching and reuse).

Selectors & Specificity

Selectors target elements: Universal (*), Type (p), Class (.card), ID (#header), Attribute (input[type="text"]), and Pseudo-classes (a:hover, li:first-child). Specificity follows: Inline > ID > Class/Attribute/Pseudo-class > Element.

The CSS Box Model

Every HTML element is rendered as a rectangular box comprising four concentric layers: Content (text/image), Padding (inner space), Border (frame around padding), and Margin (outer space separating sibling elements).

Figure 2.1: CSS Box Model (Use box-sizing: border-box to include padding & border inside width)

Modern Layout Concepts (Flexbox & CSS Grid)

  • Flexbox (display: flex): One-dimensional layout model for aligning items along a row or column using justify-content and align-items.
  • CSS Grid (display: grid): Two-dimensional layout system defining explicit rows and columns with grid-template-columns and gap.
layout.css
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
  gap: 20px;
}
.card {
  box-sizing: border-box;
  padding: 20px;
  border: 1px solid #334155;
  border-radius: 10px;
}

TOPIC 2.8

Document Type Definition (DTD)

Definition: XML (eXtensible Markup Language) is a self-describing, platform-independent markup format for storing and transporting structured data. A Document Type Definition (DTD) defines the legal building blocks, element hierarchy, and attributes of an XML document.

XML Syntax & Document Structure Rules

  • Every XML document must have a single root element and an optional prolog (<?xml version="1.0" encoding="UTF-8"?>).
  • Tags are case-sensitive, must be properly nested, and every opening tag must have a closing tag.
  • Attribute values must always be enclosed in quotes.

Internal vs. External DTD

An Internal DTD is declared inside <!DOCTYPE root [...]> within the XML file itself, whereas an External DTD resides in a separate .dtd file referenced via <!DOCTYPE root SYSTEM "file.dtd">.

student.xml (with Internal DTD)
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE student [
  <!ELEMENT student (name, branch, cgpa)>
  <!ELEMENT name (#PCDATA)>
  <!ELEMENT branch (#PCDATA)>
  <!ELEMENT cgpa (#PCDATA)>
  <!ATTLIST student roll CDATA #REQUIRED>
]>
<student roll="CS2026">
  <name>Ananya Verma</name>
  <branch>CSE</branch>
  <cgpa>8.9</cgpa>
</student>

Dynamic HTML (DHTML)

Definition: Dynamic HTML (DHTML) is not a single language, but an umbrella term describing the combination of HTML (structure), CSS (presentation), JavaScript (behavior), and the DOM (programming interface) to create animated, interactive web pages.

TOPIC 2.10

XML Schemes / XML Schemas (XSD)

Definition: An XML Schema Definition (XSD) is an XML-based language standardized by the W3C that describes the structure, element hierarchy, strong data types, and constraints of XML documents—overcoming the limitations of DTD.

XML Namespaces & XSD Features

  • XML Namespaces (xmlns): Prevent element name collisions when combining XML vocabularies (e.g., xmlns:xs="http://www.w3.org/2001/XMLSchema").
  • Rich Data Types: Supports xs:string, xs:integer, xs:decimal, xs:date, xs:boolean, plus custom simpleType restrictions (patterns, min/max) and complexType sequences.
student.xsd
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:element name="student">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="name" type="xs:string"/>
        <xs:element name="semester" type="xs:integer"/>
      </xs:sequence>
      <xs:attribute name="roll" type="xs:string" use="required"/>
    </xs:complexType>
  </xs:element>
</xs:schema>

TOPIC 2.11

Object Models

Definition: In Web Technology, an Object Model is an in-memory, language-neutral API representation of an HTML or XML document (and browser environment) as a hierarchy of objects with properties, methods, and events.

  • BOM (Browser Object Model): Represents browser-level objects like window, navigator, location, history, and screen.
  • DOM (Document Object Model): Represents the document itself (document) as a tree of Node, Element, Attr, and Text objects that scripts can traverse and mutate.

TOPIC 2.12

Presenting XML

Definition: Because XML only stores raw data without formatting instructions, Presenting XML involves attaching stylesheets using CSS or transforming XML into HTML/PDF using XSLT (eXtensible Stylesheet Language Transformations).

Approaches to XML Presentation

  1. CSS with XML: Link via <?xml-stylesheet type="text/css" href="style.css"?> to style custom tags directly (limited: cannot reorder or compute values).
  2. XSLT + XPath: XSLT uses XPath expressions to select XML nodes and transform them into HTML tables, lists, or another XML format.
catalog.xsl (XSLT Example)
<xsl:stylesheet version="1.0" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
  <xsl:template match="/">
    <html><body>
      <h2>Course List</h2>
      <ul>
        <xsl:for-each select="courses/course">
          <li><xsl:value-of select="title"/></li>
        </xsl:for-each>
      </ul>
    </body></html>
  </xsl:template>
</xsl:stylesheet>

TOPIC 2.13

Using XML Processors

Definition: An XML Processor (parser) is a software module that reads an XML document, verifies its syntax, and exposes its data to an application via an API such as DOM or SAX.

Types of XML Processors

  • Non-Validating Parser: Checks only that the XML is well-formed (matching tags, single root, proper nesting).
  • Validating Parser: Checks well-formedness and verifies that the document conforms to a DTD or XML Schema (XSD) (making it a valid XML document).

Workflow: Raw XML File → XML Processor (Lexer/Parser + Optional Validator) → Tree API (DOM) or Event Stream (SAX) → Application Logic.

TOPIC 2.14

DOM (Document Object Model)

Definition: The DOM is a W3C tree-based API that loads an entire XML or HTML document into memory as a hierarchical tree of nodes, allowing bidirectional traversal and dynamic modification.

Architecture & Practical Example

In DOM, the document is the root node, elements are branch nodes, and text/attributes are leaf/property nodes. Because the full tree resides in RAM, applications can jump to any node randomly, insert new elements, or delete nodes.

dom-parser.js
const xmlText = `<book><title>Web Tech</title><price>450</price></book>`;
const parser = new DOMParser();
const xmlDoc = parser.parseFromString(xmlText, "text/xml");
const title = xmlDoc.getElementsByTagName("title")[0].textContent;
console.log("Book Title:", title); // Output: Book Title: Web Tech

TOPIC 2.15

SAX (Simple API for XML)

Definition: SAX is an event-driven, sequential streaming API for parsing XML documents. Instead of loading the entire document into memory, it fires callback events as it reads tags from start to finish.

Working Mechanism & Callbacks

A SAX parser invokes methods on a ContentHandler as it encounters XML tokens: startDocument(), startElement(), characters(), endElement(), and endDocument(). This makes SAX ideal for multi-gigabyte XML feeds where memory is constrained.

Detailed Comparison: DOM vs. SAX

ParameterDOM (Document Object Model)SAX (Simple API for XML)
Parsing ModelTree-based (loads entire document into RAM)Event-driven / Streaming (sequential read)

TraversalRandom & bidirectional (parent, child, sibling)Forward-only, top-to-bottom

Unit 2 – Quick Revision & Exam Prep

Important Definitions

  • Box Model: Content + Padding + Border + Margin.
  • DHTML: HTML + CSS + JavaScript + DOM working together.
  • Well-Formed XML: Follows XML syntax rules.
  • Valid XML: Well-formed and conforms to a DTD or XSD.

Key Differences

  • colspan vs. rowspan: Merge columns horizontally vs. rows vertically.
  • DTD vs. XSD: Non-XML & typeless vs. XML-based & strongly typed.
  • DOM vs. SAX: In-memory read/write tree vs. low-memory read-only event stream.

Frequently Asked Exam Questions

Q1. Why were HTML4 <frameset> tags deprecated in HTML5?
Framesets broke browser back-button history, URL bookmarking, printing, and screen-reader accessibility. Modern HTML5 uses <iframe> with sandbox for isolated embeds.
Q2. When should you choose SAX over DOM for XML processing?
Choose SAX when parsing very large XML files on memory-constrained servers and you only need to extract data in a single forward pass without modifying the document.
