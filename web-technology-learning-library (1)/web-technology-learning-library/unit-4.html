TOPIC 4.1

Web 2.0: Interactive and Social Web

Definition: Web 2.0 refers to the second generation of the World Wide Web characterized by dynamic, participatory, user-generated content, social collaboration, and rich browser-based applications.

Popularized by Tim O'Reilly (2004), Web 2.0 shifted users from passive readers (Web 1.0) to active creators—commenting, blogging, editing wikis, and sharing media on platforms like Wikipedia, YouTube, and GitHub.

Comparison: Web 1.0 vs. Web 2.0 vs. Web 3.0

Primary FocusStatic information publishingSocial interaction & user-generated contentMachine-readable knowledge (RDF) & decentralization
Content CreationSite owners / webmastersEnd users, communities, creatorsUsers + AI/semantic agents + linked data

TOPIC 4.2

Blogs (Weblogs)

Definition: A Blog is a frequently updated website or online journal displaying posts in reverse chronological order, typically managed via a Content Management System (CMS) like WordPress or Ghost.

Key Features: Permalinks (permanent URLs per post), categories/tags, reader comment threads, and RSS/Atom feeds for syndication. Applications: Engineering blogs, personal portfolios, journalism, and product changelogs. Limitations: Requires moderation against spam and consistent content upkeep.

TOPIC 4.3

Wikis

Definition: A Wiki is a collaborative web application that allows multiple users to create, edit, link, and maintain shared pages directly in a browser using simplified markup (Wikitext or Markdown).

Working Mechanism: Every edit is stored in a revision history database, enabling instant rollback if vandalism or errors occur. Real-world Examples: Wikipedia (MediaWiki), GitHub Wikis, Confluence. Advantages: Rapid crowd-sourced knowledge accumulation; Limitations: Susceptible to edit wars or unverified claims without editorial review.

← Previous: BlogsNext: Social Networking Sites →
TOPIC 4.4

Social Networking Sites (SNS)

Definition: Social Networking Sites are online platforms where users build public/semi-public profiles, articulate a social graph of connections, and share real-time updates, media, and messages.

Architecture: Relies on graph databases or distributed caches for friend/follower relationships, personalized news-feed ranking pipelines, and CDNs for media delivery. Examples: LinkedIn, X, Instagram. Limitations: Privacy risks, algorithmic echo chambers, and misinformation spread.

TOPIC 4.5

Technologies Behind Web 2.0

Definition: Technologies Behind Web 2.0 encompass the client- and server-side stack—AJAX, RESTful APIs, JSON, DOM scripting, CSS3, and Rich Internet Applications (RIAs)—that make browser apps feel as responsive as desktop software.

  • Asynchronous Data Exchange: AJAX + JSON replaced heavy full-page reloads.
  • RESTful Web Services: Lightweight HTTP endpoints returning JSON payloads.
  • Dynamic UI: JavaScript DOM manipulation paired with CSS3 transitions.

TOPIC 4.6

AJAX (Role in Web 2.0)

Definition: In Web 2.0, AJAX serves as the foundational interaction engine enabling live likes, inline comments, drag-and-drop maps (Google Maps), and real-time search suggestions without interrupting the user's workflow.

Advantages: Desktop-like responsiveness and lower server bandwidth. Limitations: Requires careful management of browser history (History API), loading states, and SEO crawlability.

TOPIC 4.7

RSS (Really Simple Syndication)

Definition: RSS is a standardized XML web feed format that allows publishers to syndicate updates (news articles, blog posts, podcasts) so feed readers and aggregators can fetch them automatically.

feed.xml (RSS 2.0)
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>CSE Department Notices</title>
    <link>https://university.edu/cse</link>
    <description>Latest academic announcements</description>
    <item>
      <title>End-Semester Exam Schedule</title>
      <link>https://university.edu/cse/exams</link>
      <pubDate>Mon, 18 Nov 2026 09:00:00 GMT</pubDate>
    </item>
  </channel>
</rss>

TOPIC 4.8

Ruby on Rails

Definition: Ruby on Rails (RoR) is an open-source, server-side web application framework written in Ruby that follows the Model–View–Controller (MVC) architectural pattern.

  • Convention over Configuration (CoC): Sensible defaults eliminate excessive XML/boilerplate config files.
  • DRY (Don't Repeat Yourself): Every piece of knowledge has a single, unambiguous representation.
  • ActiveRecord ORM: Maps database tables directly to Ruby classes. Real-world Examples: GitHub, Shopify, Airbnb (early architecture).

TOPIC 4.9

Open APIs

Definition: An Open API (Public API) is a publicly documented programming interface—typically RESTful JSON over HTTPS—that allows external developers to access a platform's data or services programmatically.

Working & Security: Developers authenticate via API Keys or OAuth 2.0 tokens, while providers enforce rate limiting and document endpoints using the OpenAPI Specification (Swagger). Examples: Google Maps API, Stripe API, GitHub REST API.

TOPIC 4.10

Web 3.0: Semantic Web

Definition: Proposed by Tim Berners-Lee, the Semantic Web (Web 3.0) extends the Web with standardized metadata so machines can understand the meaning and relationships of data, not just display text.

Core Stack: Uses URIs for naming, RDF for structured triples, OWL (Web Ontology Language) for defining domain relationships, and SPARQL for querying knowledge graphs (e.g., Wikidata, Schema.org rich snippets in Google Search).

TOPIC 4.11

Widgets

Definition: A web Widget is a portable, self-contained UI component or mini-application (such as a weather ticker, live chat box, or currency converter) that can be embedded into any third-party web page.

Implemented via <script> embeds, sandboxed <iframe> containers, or modern W3C Web Components (Custom Elements + Shadow DOM) to isolate styles from the host page.

TOPIC 4.12

Mashups

Definition: A Mashup is a web application that combines data, presentation, or functionality from two or more external Open APIs to create a new unified service.

Example: A real-estate portal combining housing listings from a property database with interactive street maps from Google Maps API and transit schedules from a city Open API. Limitation: Dependent on upstream API uptime and licensing terms.

TOPIC 4.13

RDF (Resource Description Framework)

Definition: RDF is a W3C data model for representing machine-readable knowledge on the Semantic Web as directed graphs composed of Subject – Predicate – Object triples.

In a triple, the Subject is a resource URI, the Predicate is a property/relationship URI, and the Object is another resource or literal value (e.g., <Tim_Berners-Lee> <invented> <WWW>).

course.rdf (RDF/XML)
<rdf:RDF xmlns:rdf="http://www.w3.org/1999/02/22-rdf-syntax-ns#"
         xmlns:dc="http://purl.org/dc/elements/1.1/">
  <rdf:Description rdf:about="https://example.edu/courses/webtech">
    <dc:title>Web Technology</dc:title>
    <dc:creator>Department of CSE</dc:creator>
  </rdf:Description>
</rdf:RDF>

TOPIC 4.14

Web-Based Information Systems (WBIS)

Definition: A Web-Based Information System is an enterprise software system that uses web technologies (browsers, HTTP, application servers, databases) to store, process, and deliver organizational information.

Architecture: Typically 3-tier—Presentation Tier (HTML/CSS/JS), Logic Tier (Java/Node/Python/Rails), and Data Tier (SQL/NoSQL). Examples: University ERP portals, Hospital Management Systems, Online Banking.

TOPIC 4.15

Search Engines

Definition: A Web Search Engine is a large-scale information retrieval system that discovers web pages, indexes their content, and ranks relevant results for user queries in milliseconds.

Figure 4.1: Search Engine Crawling, Indexing, and Ranking Pipeline
  • Crawling: Automated bots (spiders) follow hyperlinks while respecting robots.txt.
  • Indexing: Builds an inverted index mapping keywords to document IDs and positions.
  • Ranking: Evaluates authority (e.g., PageRank link analysis), semantic relevance, and page speed.

TOPIC 4.16

Recommender Systems

Definition: A Recommender System is an information-filtering engine that predicts user preferences and suggests relevant items (products, movies, courses) based on user behavior or item attributes.

ApproachHow It WorksStrength / Limitation
Content-Based FilteringRecommends items with attributes similar to items the user liked previously (e.g., genre, tags).No cold-start for new items; limited to narrow user history ("filter bubble").
Collaborative FilteringFinds users with similar rating/click patterns ("Users who bought X also bought Y").Discovers diverse interests; suffers from cold-start when new users/items have zero ratings.
Hybrid SystemsCombines content features and collaborative user-item matrices (used by Netflix, Amazon, Spotify).Higher accuracy and resilience against cold-start.

TOPIC 4.17

Benefits of Blockchain

Definition: A Blockchain is a distributed, append-only digital ledger where verified transactions are grouped into cryptographic blocks, linked sequentially via hash pointers, and maintained across peer nodes via a consensus mechanism.

Core Concepts & Benefits

  • Decentralization: Eliminates single points of failure and central intermediaries.
  • Immutability & Tamper Resistance: Altering any historical transaction invalidates its cryptographic hash and all subsequent blocks.
  • Transparency & Auditability: Participants can independently verify transactions on shared ledgers.
  • Consensus Mechanisms: Proof of Work (PoW) or Proof of Stake (PoS) ensure distributed agreement without a central authority.

Limitations: Lower transaction throughput than centralized databases, storage growth, and energy/cost trade-offs depending on consensus.

Edge Computing

Definition: Edge Computing processes data and executes web logic close to the physical source of data or end user (at CDN edge nodes, ISP gateways, or local devices) rather than routing every request to a distant centralized cloud data center.

TOPIC 4.19

Dark Mode in Web Development

Definition: Dark Mode is a UI color scheme that displays light-colored text and controls on dark backgrounds, reducing eye strain in low-light environments and saving power on OLED/AMOLED displays.

Implementation with CSS Variables & prefers-color-scheme

dark-mode.css
:root {
  --bg: #ffffff;
  --text: #111827;
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0b1020;
    --text: #f1f5ff;
  }
}
[data-theme="dark"] {
  --bg: #0b1020;
  --text: #f1f5ff;
}
body {
  background-color: var(--bg);
  color: var(--text);
}

Best Practices: Avoid pure #000000 with pure #FFFFFF (can cause halation); use deep slate/navy surfaces like #0B1020 and maintain WCAG ≥4.5:1 text contrast.

Unit 4 – Quick Revision & Exam Prep

Important Definitions

  • Web 2.0: Participatory social web (UGC, AJAX, REST).
  • RDF Triple: Subject – Predicate – Object graph statement.
  • Inverted Index: Maps words → list of documents for fast search.
  • Edge Computing: Computation near users to minimize latency.

Key Differences

  • Content-Based vs. Collaborative: Item similarity vs. user behavior similarity.
  • Cloud vs. Edge: Centralized high-compute vs. distributed low-latency.
  • Widget vs. Mashup: Single embeddable UI piece vs. multi-API combined app.

Frequently Asked Exam Questions

Q1. What are the two core design principles of Ruby on Rails?
Convention over Configuration (CoC) and Don't Repeat Yourself (DRY), built around the MVC architecture.
Q2. What is the "cold-start problem" in Recommender Systems?
It occurs when a new user or new item has insufficient interaction history, making it difficult for collaborative filtering to generate accurate recommendations.
