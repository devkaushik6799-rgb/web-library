TOPIC 1.1

History of the Internet

Definition: The Internet is a global, decentralized "network of networks" that interconnects millions of private, public, academic, business, and government networks using standardized communication protocols—primarily the TCP/IP (Transmission Control Protocol / Internet Protocol) suite.

Introduction & Conceptual Evolution

Unlike a single centralized computer network, the Internet was engineered to survive partial outages and connect heterogeneous hardware. Its core innovation was packet switching—breaking data into small packets, routing each packet independently across available network links, and reassembling them at the destination.

Understandable Timeline of the Internet

Year / EraMilestoneKey Significance
1969ARPANET LaunchesFunded by the U.S. Department of Defense (ARPA), the first four nodes (UCLA, Stanford, UCSB, Utah) connected via packet switching.
1971First Network EmailRay Tomlinson sent the first email across ARPANET and introduced the @ symbol to separate user and host names.
1974–1983TCP/IP StandardizedVint Cerf and Bob Kahn designed TCP/IP. On January 1, 1983 ("Flag Day"), ARPANET officially switched from NCP to TCP/IP—the birth of the modern Internet.
1983–1985DNS & NSFNETPaul Mockapetris invented the Domain Name System (DNS); the National Science Foundation created NSFNET, linking university supercomputing centers.
1989–1991World Wide WebTim Berners-Lee at CERN proposed and built the WWW (HTTP, HTML, URL, and the first web browser/server).
1993–1995Mosaic & CommercializationNCSA Mosaic popularized graphical web browsing; NSFNET was decommissioned, opening the Internet to commercial ISPs and e-commerce.
2000s–PresentBroadband, Mobile & CloudFiber optics, 4G/5G, smartphones, cloud computing, IPv6 adoption, and HTTP/2 & HTTP/3 transformed the Internet into everyday global infrastructure.
Important Points for Examinations
  • Packet Switching vs. Circuit Switching: ARPANET used packet switching (shared bandwidth, resilient routing) instead of telephone-style circuit switching (dedicated path).
  • TCP/IP Adoption (1983): Often cited in exams as the technical birth of the Internet because it enabled diverse networks to interoperate.
  • Internet vs. WWW: The Internet is the physical/logical network infrastructure; the World Wide Web is one application service running on top of it.

TOPIC 1.2

World Wide Web (WWW)

Definition: The World Wide Web (WWW) is an open, global information space of interlinked hypertext documents and multimedia resources accessed via the Internet using Uniform Resource Locators (URLs) and transferred over HTTP/HTTPS.

Introduction & Core Pillars

Invented by Tim Berners-Lee at CERN in 1989, the WWW solved the problem of sharing documents across incompatible computer systems. It rests on three foundational standards:

  • URL (Uniform Resource Locator): A unique address identifying a resource on the Web (e.g., https://example.edu:443/notes/unit1.html).
  • HTTP (HyperText Transfer Protocol): The application-layer protocol governing how clients request resources and servers respond.
  • HTML (HyperText Markup Language): The markup format used to structure text, media, and hyperlinks connecting documents together.

Working Mechanism (Client–Server Web Model)

  1. A user enters a URL or clicks a hyperlink in a web browser (client).
  2. The browser resolves the domain name to an IP address via DNS.
  3. The browser opens a TCP (and TLS for HTTPS) connection to the web server and sends an HTTP request.
  4. The web server locates or dynamically generates the requested resource and returns an HTTP response containing status, headers, and HTML/media payload.
  5. The browser parses the HTML, fetches linked CSS/JS/images, and renders the interactive page.

TOPIC 1.3

HTML (HyperText Markup Language)

Definition: HTML is the standard markup language used to structure and present content on the World Wide Web. It uses nested tags and attributes to define headings, paragraphs, links, images, forms, and semantic page regions.

Key Characteristics

  • Markup, Not Programming: HTML describes document structure and meaning rather than algorithmic control flow.
  • Platform Independent: Any standards-compliant browser on Windows, Linux, macOS, Android, or iOS renders the same HTML document.
  • Hypertext Capability: The <a href="..."> anchor tag connects documents across servers worldwide.
  • HTML5 Semantics: Modern HTML5 introduces semantic landmarks like <header>, <nav>, <main>, <article>, and <footer> for accessibility and SEO.

Standard HTML5 Document Structure

index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>University Notice Board</title>
</head>
<body>
  <header>
    <h1>Department of Computer Science</h1>
  </header>
  <main>
    <p>Exam schedules are available on the <a href="schedule.html">portal</a>.</p>
  </main>
</body>
</html>

Line-by-line explanation: <!DOCTYPE html> triggers standards mode; <html> is the root element; <head> holds metadata not drawn on the canvas; <body> contains visible elements rendered by the browser.

TOPIC 1.4

Protocols – HTTP (HyperText Transfer Protocol)

Definition: HTTP is an application-layer, stateless client–server protocol used to transfer hypermedia documents (HTML, JSON, images, video) across the Web. Its encrypted counterpart, HTTPS, layers HTTP over TLS (Transport Layer Security).

Purpose & Important Characteristics

  • Request–Response Model: The client (browser) always initiates a request; the server returns a response.
  • Stateless: Each request is independent—the server retains no memory of prior requests unless state is added via cookies, sessions, or tokens.
  • Media Independent: Any data type can be sent as long as both sides specify the MIME Content-Type header.
  • Default Ports: Port 80 for HTTP; Port 443 for HTTPS.

Request–Response Architecture

HTTP Status Code Categories

  • 1xx (Informational): Request received, continuing process (e.g., 101 Switching Protocols).
  • 2xx (Success): Action succeeded (200 OK, 201 Created, 204 No Content).
  • 3xx (Redirection): Further action needed (301 Moved Permanently, 304 Not Modified).
  • 4xx (Client Error): Bad syntax or unauthorized (400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found).
  • 5xx (Server Error): Server failed to fulfill a valid request (500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable).

HTTP Headers & HTTPS

Headers carry metadata as key-value pairs: Host, User-Agent, Accept, Authorization (request), and Content-Type, Cache-Control, Set-Cookie (response). HTTPS wraps HTTP inside TLS, providing three guarantees: confidentiality (encryption), integrity (tamper detection), and authentication (digital certificates issued by a Certificate Authority).

TOPIC 1.5

Protocols – SMTP (Simple Mail Transfer Protocol)

Definition: SMTP is an application-layer, text-based push protocol used to send and relay outgoing electronic mail from a mail client to a mail server and between mail servers across the Internet.

Purpose & Working Mechanism

SMTP handles outgoing mail delivery (not mailbox retrieval). It operates over TCP on Port 25 (server-to-server relay), Port 587 (authenticated client submission with STARTTLS), or Port 465 (SMTPS).

  1. The sender's Mail User Agent (MUA, e.g., Thunderbird) connects to their Mail Submission Agent / SMTP server.
  2. The client greets the server with HELO or EHLO (Extended SMTP).
  3. The client identifies sender (MAIL FROM:) and recipient (RCPT TO:).
  4. After DATA, the message headers and body are transmitted, ending with a single period (.) on its own line.
  5. If the recipient is on another domain, the sender's SMTP server queries DNS for the recipient domain's MX (Mail Exchange) record and relays the email to the destination SMTP server.

Characteristics & Practical Example

  • Push Protocol: Pushes messages toward the recipient's mail server.
  • 7-bit ASCII Limitation: Classic SMTP only supports 7-bit ASCII text; binary attachments require MIME encoding.
  • Store-and-Forward: Queues messages and retries if the destination server is temporarily unreachable.

TOPIC 1.6

Protocols – POP3 (Post Office Protocol Version 3)

Definition: POP3 is a simple, standard pull protocol used by email clients to retrieve messages from a remote mail server to a local device.

Working Mechanism (Three States)

POP3 runs over TCP on Port 110 (plain) or Port 995 (POP3S with TLS) and progresses through three states:

  1. Authorization State: Client authenticates with USER and PASS commands.
  2. Transaction State: Client lists message sizes (LIST), downloads messages (RETR), and optionally marks them for deletion (DELE).
  3. Update State: Triggered upon QUIT; the server permanently deletes messages marked with DELE and closes the connection.

Characteristics, Advantages & Limitations

  • Download-and-Delete Default: Historically removes mail from the server after download, freeing server storage and enabling full offline reading.
  • Limitation: Poor support for multi-device synchronization—folders, read/unread flags, and sent items stay local to one computer.

TOPIC 1.7

MIME (Multipurpose Internet Mail Extensions)

Definition: MIME is an Internet standard that extends the format of email (and HTTP) messages to support non-ASCII character sets (UTF-8), multimedia attachments (images, audio, video, PDFs), and multi-part message bodies.

Why MIME is Needed & Key Headers

Because SMTP was originally restricted to 7-bit US-ASCII text, binary files like JPEGs or ZIP archives could not be transmitted directly. MIME solves this by encoding binary data into ASCII characters (most commonly Base64) and adding descriptive headers:

  • MIME-Version: 1.0 — Indicates the message conforms to MIME.
  • Content-Type: type/subtype — Identifies media format (e.g., text/html, image/png, application/pdf, multipart/mixed).
  • Content-Transfer-Encoding — Specifies encoding used (7bit, quoted-printable, base64).
  • Content-Disposition — Hints whether content should display inline or as an attachment with a filename.
MIME Multipart Email Example
MIME-Version: 1.0
Content-Type: multipart/mixed; boundary="BOUNDARY_123"

--BOUNDARY_123
Content-Type: text/plain; charset="UTF-8"

Hello, please find the syllabus PDF attached.
--BOUNDARY_123

TOPIC 1.8

IMAP (Internet Message Access Protocol)

Definition: IMAP (currently IMAP4rev1/rev2) is an application-layer email retrieval protocol that stores messages on the mail server and synchronizes folders, flags, and message state across multiple client devices.

Working Mechanism & Characteristics

Operating over TCP Port 143 (or Port 993 for IMAPS with TLS), IMAP keeps the authoritative mailbox on the server. Clients fetch headers first for fast browsing and download attachments only on demand. Actions such as reading, starring, moving to folders, or deleting sync bidirectionally across phones, laptops, and webmail.

TOPIC 1.9

Domain Name Server (DNS)

Definition: The Domain Name System (DNS) is the hierarchical, distributed naming system of the Internet that translates human-readable domain names (such as www.example.edu) into machine-routable IP addresses (such as 93.184.216.34).

DNS Hierarchy & Common Record Types

  • Root Servers (.): 13 logical root server clusters worldwide that direct queries to Top-Level Domain (TLD) servers.
  • TLD Servers: Manage extensions like .com, .org, .edu, .in.
  • Authoritative Name Servers: Hold the actual DNS zone records for a specific domain.
  • Key Record Types: A (IPv4 address), AAAA (IPv6 address), CNAME (alias), MX (mail server), NS (name server), TXT (verification/SPF).

Step-by-Step Domain Resolution Process

Figure 1.2: Recursive and Iterative DNS Resolution Workflow (Port 53 UDP/TCP)
  1. Cache Check: The browser and OS check their local DNS cache (and hosts file). If missed, the query goes to the configured Recursive DNS Resolver (ISP or 8.8.8.8 / 1.1.1.1).
  2. Root Server Query: If uncached, the recursive resolver asks a Root Server for www.example.edu. The Root Server replies with the referral to the .edu TLD server.
  3. TLD Server Query: The resolver queries the .edu TLD server, which responds with the IP of the authoritative name server for example.edu.
  4. Authoritative Query: The resolver queries the authoritative server, which returns the exact A (or AAAA) IP address record.
  5. Caching & Response: The resolver caches the IP for its TTL (Time To Live) and returns it to the browser, which then connects to the web server.

TOPIC 1.10

Web Browsers

Definition: A Web Browser is a client-side software application that retrieves resources from web servers over HTTP/HTTPS, interprets HTML, CSS, and JavaScript, and renders interactive web pages to the user.

Browser Architecture & Core Components

  • User Interface (UI): Address bar, back/forward buttons, tabs, and bookmarks.
  • Browser Engine: Marshals actions between the UI and the rendering engine.
  • Rendering Engine: Parses HTML into the DOM tree and CSS into the CSSOM tree, combines them into a Render Tree, computes layout, and paints pixels (e.g., Blink in Chrome/Edge, Gecko in Firefox, WebKit in Safari).
  • Networking Layer: Handles HTTP/HTTPS requests, DNS lookups, TLS handshakes, and caching.
  • JavaScript Engine: Parses and executes JS code using Just-In-Time (JIT) compilation (e.g., V8, SpiderMonkey, JavaScriptCore).
  • Data Persistence: Manages Cookies, localStorage, sessionStorage, and IndexedDB.

TOPIC 1.11

Web Servers

Definition: A Web Server is hardware and/or software (such as Apache HTTP Server, Nginx, or IIS) that stores web assets, listens on TCP ports 80/443, processes incoming HTTP/HTTPS requests, and delivers responses to clients.

Working Mechanism & Features

  1. Listen: The server binds to a socket (e.g., 0.0.0.0:443) and awaits client connections.
  2. Parse Request: Reads the HTTP method, path, headers, and virtual host (Host: example.com).
  3. Static vs. Dynamic Processing: Static files (HTML, CSS, PNG) are read directly from disk. Dynamic requests are forwarded via reverse proxy or gateway (CGI/WSGI/FastCGI) to an application runtime (Node.js, Python, Java, PHP) and database.
  4. Respond & Log: Returns the HTTP status code and payload, and records access/error logs.

Key Capabilities

  • Virtual Hosting: Serving multiple domain names from a single physical server IP.
  • Reverse Proxying & Load Balancing: Distributing traffic across backend app servers (a strength of Nginx).
  • TLS Termination, Compression (Gzip/Brotli), & Caching: Improving security and latency.

Unit 1 – Quick Revision & Exam Prep

High-yield definitions, key protocol ports, differences, and university exam FAQs.

Important Definitions & Ports

  • HTTP / HTTPS: Stateless web transfer (Ports 80 / 443).
  • SMTP: Outgoing mail push protocol (Ports 25 / 587 / 465).
  • POP3: Download-and-delete mail pull (Ports 110 / 995).
  • IMAP: Server-synced multi-device mail (Ports 143 / 993).
  • DNS: Domain-to-IP resolution (Port 53).
  • MIME: Enables attachments & UTF-8 over SMTP/HTTP.

Key Differences to Remember

  • Internet vs. WWW: Infrastructure vs. hypertext service.
  • GET vs. POST: URL-visible, idempotent retrieval vs. body-carried state mutation.
  • POP3 vs. IMAP: Local single-device storage vs. server-side multi-device sync.
  • Static vs. Dynamic Web Server: Serves pre-built files vs. executes backend code per request.

Frequently Asked Exam Questions

Q1. Why is HTTP called a stateless protocol, and how do web apps maintain sessions?
HTTP servers do not retain client state between independent requests. Web apps maintain state using HTTP Cookies (Set-Cookie), server-side session IDs, or Authorization tokens (JWT).
Q2. Explain the role of MX records in email delivery.
When an SMTP server needs to deliver mail to another domain, it queries DNS for that domain's MX (Mail Exchange) record to discover the hostname of the receiving mail server.
Q3. What is the difference between a Browser Engine and a Rendering Engine?
The Browser Engine coordinates communication between the browser UI and the Rendering Engine, whereas the Rendering Engine parses HTML/CSS into DOM/CSSOM trees and paints the page on screen.
